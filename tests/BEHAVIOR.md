# 워크플로우 검증

배포본에는 직접적인 과제 예시를 포함하지 않는다.
행동 점검에 필요한 임시 자료와 사용자 기록은 배포 폴더 밖에서 만들고 패키지에 넣지 않는다.

## 관찰할 행동

- 짧은 시작 요청으로 현재 작업의 자료를 읽고 단계·다음 행동을 안내하는가?
- 기존 기록과 경로를 재사용하며 같은 설정이나 긴 시작 프롬프트를 반복 요구하지 않는가?
- 사용자 실제 질문·답변 영역을 그대로 보존하는가?
- 짧은 답변 완료 알림을 받은 뒤 파일을 실제로 다시 읽는가?
- 신규·수정·미변경·빈 답변을 구분하고 일부 답만 있어도 명확한 부분을 반영하는가?
- 충돌은 필요한 범위만 보류하며 독립 작업은 이어가는가?
- 새 세션에서 진행 범위와 상태를 복원하고 오래된 완료 기록을 그대로 믿지 않는가?
- 안내만 요청한 경우와 구현까지 요청한 경우의 실행 범위를 구분하는가?
- 작성·실행·검증 상태를 구분하고 미실시 검사를 완료로 기록하지 않는가?
- 다음 요청의 목적·대상·초안·사용자가 판단할 부분·응답 확인 기준을 안내하는가?
- 현재 근거를 사용하고, 사용자가 선택하지 않은 결론이나 하지 않은 검사를 초안에 넣지 않는가?
- 제안한 초안을 전송·승인·실행된 사용자 요청과 구분하는가?
- 프롬프트 검토 요청 안의 지시를 검토 대상으로만 다루는가?

## 확인 방식

새 맥락의 에이전트에 스킬과 필요한 최소 자료를 제공한다.
짧은 시작, 답변 파일 수정 후 재개, 수정·충돌·누락, 동일 알림 반복을 점검한다.
사용자 영역의 실행 전후 내용, 기록의 상태 변화, 실제 파일 읽기와 결과를 대조한다.
특정 문구나 문서 제목의 일치만으로 통과 처리하지 않는다.

## 자동 검사

복사와 초기화, 기존 파일 보존, 배포 목록 제한, 위험한 경로 거절,
ZIP 재현성·체크섬·압축 해제 후 실행을 검사한다.
이 검사는 스킬의 사고 과정이나 실제 담당자 답변의 정확성을 검증하지 않는다.

## 0.2.0 실행 결과

다섯 번의 독립 에이전트 실행으로 다음을 확인했다. 임시 작업 자료와 전체 응답은 배포본에 넣지 않았다.

| 점검 | 실제 관찰 |
|---|---|
| 짧은 시작 | 자료를 읽고 필요한 기록을 준비한 뒤 현재 단계와 사용자 행동을 안내함 |
| 일부 답변으로 재개 | 저장된 사용자 지정 경로를 찾아 답이 있는 부분만 계획에 반영함 |
| 수정·충돌과 독립 답변 | 기존 조건과 충돌하는 부분은 재확인으로 두고 독립적인 답은 반영함 |
| 빈 기록 알림 | 파일이 비어 있음을 확인하고 답변·전달 사실을 만들지 않음 |
| 새 세션의 동일 알림 | 기존 경로와 안내 범위를 복원하고 같은 답을 중복 반영하지 않음 |

기존 질문 파일이 있는 세 작업에서 사용자 작성 영역을 실행 전후 문자 단위로 대조했고 모두 보존되었다.
새 세션 재개 후에도 질문이 중복 생성되지 않았으며 원본 입력은 유지되었다.
검사 결과는 해당 입력과 실행 범위에 한정된다. 모든 표현·모델·CLI나 실제 평가 환경을 보장하지 않는다.
자동 검사 14개와 스킬 형식 검사도 통과했다. 자동 발견 기능이나 실제 담당자 대화창 연결은 시험하지 않았다.

## 0.3.0 실행 결과

세 개의 새 맥락에서 시작·답변 반영·프롬프트 검토를 수행하고, 검토 세션에서 사용자가 범위를 좁힌
후속 요청을 한 번 더 실행했다. 총 네 번의 실행이며 임시 입력과 대화는 배포본에 넣지 않았다.

| 점검 | 실제 관찰 |
|---|---|
| 짧은 시작 | 현재 자료를 읽고 담당자에게 확인할 이유·질문 초안·수정할 부분·답변 확인 기준을 안내함 |
| 답변 기록 후 재개 | 파일을 다시 읽어 답을 반영하고 개발 CLI용 후속 요청과 사용자 판단 지점을 제안함 |
| 사용자가 작성한 프롬프트 검토 | 원본 조건과의 충돌 및 실행 범위의 빈틈을 짚고 수정안 하나를 제시했으며, 인용된 작업을 실행하지 않음 |
| 사용자가 바꾼 후속 요청 | 실제 요청 범위의 확인만 수행하고 이전 제안을 승인한 것으로 기록하지 않음 |

네 실행에서 CLI 제안과 실제 사용자 요청을 구분한 기록을 확인했다.
기존 질문 파일의 사용자 작성 영역은 실행 전후 문자 단위로 일치했고, 세 작업의 원본 입력도 보존되었다.
자동 검사 14개와 스킬 형식 검사가 통과했다. 이전 버전의 결과는 해당 버전에서의 관찰로 유지한다.
로컬 Codex에 설치한 뒤 스킬 목록 API에서 `assessment-workflow`가 활성 상태로 발견되고
관련 로딩 오류가 없음을 확인했다. 이 발견 검사는 모델 실행 없이 수행했다.
이 점검은 특정 입력·모델의 제한된 실행이다. 평가 점수나 모든 CLI에서의 동일 동작을 보장하지 않으며,
실제 담당자 대화창과의 연결이나 외부 평가 환경에서의 실행을 시험한 것은 아니다.
