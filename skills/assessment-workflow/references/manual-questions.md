# 사용자가 직접 전달하고 기록하는 확인 절차

## 질문 준비

현재 자료에서 답을 찾을 수 있는지 먼저 확인한다. 질문할 가치가 있는 정보는
답에 따라 업무 규칙, 결과의 의미, 검증 기준, 중요한 작업 순서가 달라지는 정보다.
이미 정해진 조건을 재질문하거나 담당자에게 구현 방식의 정답을 요구하지 않는다.

질문 하나에 하나의 판단을 연결한다. 관련 질문은 함께 제시해도 된다.
`QUESTIONS.md`에서 다음 필드로 질문을 준비한다.

- 질문 ID와 상태
- 관찰한 내용과 현재 자료의 위치
- 빠진 정보 또는 서로 충돌하는 조건
- 왜 확인이 필요한지, 답에 따라 무엇이 달라지는지
- 그대로 전달할 질문 문구
- 답을 기다리는 동안 진행 가능한 작업

실제로 확인한 자료만 근거로 쓰고, 관찰하지 않은 차이나 수치를 만들지 않는다.
질문은 가능한 선택지를 설명할 수 있지만 원하는 답을 유도하지 않는다.

## 사용자에게 넘기기

사용자가 할 행동을 명확히 안내한다.

1. 준비한 질문을 별도 대화창의 담당자에게 직접 전달한다.
2. 받은 답변을 작업폴더의 `QUESTIONS.md` 해당 질문 아래에 기록한다.
3. 원문 인용인지 사용자의 요약인지 표시하고, 답변자와 확인 가능한 출처·시점을 적는다.
4. CLI에 수정한 파일 경로와 질문 ID를 알려 다시 읽게 한다.

이 절차에는 대화창 연동, 자동 전송, 자동 수신 기능이 없다.
원문을 기록하기 어려우면 사용자 요약임을 명시한다. 모르는 시점·출처는 미상으로 남긴다.
불필요한 개인정보나 비밀값을 복사하도록 요구하지 않는다.

## 상태와 역할

| 상태 | 의미와 변경 근거 |
|---|---|
| 준비 | 질문 초안이 있음. 전송한 것은 아님 |
| 사용자 전달 | 사용자가 실제 전달했다고 기록함 |
| 답변 기록 | 사용자가 받은 답을 기록함. 해석·충돌 검토는 별도 |
| 재확인 필요 | 답이 모호하거나 기존 조건과 충돌함 |
| 반영 | 명확해진 조건을 계획 또는 결과물에 반영함. 검증 상태는 별도 기록 |
| 대체 | 뒤의 질문·답변으로 대체됨. 과거 내용과 연결을 보존함 |

기록이 없으면 준비 상태를 유지한다. 기다린 시간은 답변이 아니다.
사용자가 대화에서 실제 답을 직접 제공하고 기록을 요청한 경우에는 AI가 옮겨 적을 수 있다.
이때 출처는 사용자 전달로 표시하며 담당자와 직접 대화한 것처럼 쓰지 않는다.

## 답변을 다시 읽은 뒤

답변의 내용, 사용자의 요약, AI의 해석을 섞지 않는다.
기존 문서와 충돌하거나 적용 범위가 불분명하면 재확인할 부분만 짚는다.
명확한 답은 `PLAN.md`의 관련 조건과 연결하고 영향받는 결과물·검사를 갱신한다.
답변이 변경되면 이전 기록을 지우지 말고 무엇을 대체하는지 적는다.
이미 만든 결과의 유효성이 달라졌다면 사용자가 알 수 있게 표시하고 다시 확인한다.

## 답이 없을 때

그 정보에 의존하지 않는 작업은 계속한다.
의존하는 작업은 미확정 상태를 유지하거나 명시적인 잠정안으로 분리한다.
정답에 영향을 주는 가정을 숨긴 채 완료로 보고하지 않는다.
담당자가 기술 설계까지 대신 결정해 줄 것이라고 가정하지 않는다.
