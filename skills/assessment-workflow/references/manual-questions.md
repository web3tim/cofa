# 사용자가 직접 질문하고 기록하는 절차

## 질문 준비

현재 자료에서 답을 찾을 수 있는지 먼저 확인한다.
답에 따라 업무 규칙·결과 의미·검증 기준·중요한 작업 순서가 달라지는 정보부터 확인한다.
질문은 관찰 근거, 빠진 정보, 답에 따라 바뀌는 판단, 전달할 초안으로 구성한다.
담당자에게 구현 방식의 정답을 대신 결정하도록 요구하지 않는다.
관찰하지 않은 차이나 수치를 만들어 질문하지 않는다.

## 기록의 소유권

`QUESTIONS.md`는 질문별로 세 영역을 구분한다.

| 영역 | 작성 주체와 내용 |
|---|---|
| CLI 준비 | 질문 ID, 근거, 미확인 사항, 질문 초안, 대기 중 가능한 작업 |
| 사용자 기록 | 실제 질문한 내용, 전달 여부, 받은 답, 원문·요약 구분, 출처·시점 |
| CLI 검토 | 답변 해석, 충돌, 반영할 조건, 변경 영향, 반영 상태와 증거 |

CLI는 실제로 질문한 내용이나 받은 답을 사용자 대신 작성·정정하지 않는다.
사용자 영역을 그대로 보존하고 해석·오류 지적·재확인 요청은 CLI 검토 영역에 쓴다.
초안은 실제 질문과 다를 수 있다. 답변을 해석할 때 사용자가 실제로 질문한 범위를 우선 확인한다.
기존 파일에 영역 구분이 없으면 사용자 기록은 그대로 두고 별도의 CLI 검토 항목을 추가한다.

## 사용자가 할 일

1. CLI가 짚은 부족한 정보를 확인하고 담당자에게 직접 질문한다.
2. 실제 질문과 받은 답을 알려진 `QUESTIONS.md`의 사용자 영역에 직접 기록한다.
3. 원문인지 요약인지 표시하고 알 수 있는 출처·시점을 적는다. 모르는 항목은 미상으로 남긴다.
4. CLI에 “기록했어” 또는 “답변 적었어”라고 알린다.

CLI는 기록 위치를 안내하고 PLAN에 저장한다. 다음부터 같은 경로를 다시 요구하지 않는다.
담당자 대화창 연동·자동 전송·자동 수신은 없다. 말로만 답변했다고 알려도 파일을 실제로 읽어 확인한다.

## 다시 읽은 뒤의 판단

- 빈 기록: 전송·답변을 추정하지 않는다. 필요한 사용자 기록 항목을 짚는다.
- 일부 답변: 답이 있는 부분만 검토·반영하고 나머지는 대기한다.
- 명확한 답변: 계획과 관련 결과·검사에 연결한다. 검사는 실행 후에만 결과를 적는다.
- 모호하거나 충돌하는 답변: 영향받는 부분을 보류하고 초점을 좁힌 재확인 질문을 제안한다.
- 수정된 답변: 이전 반영 내용과의 차이를 남기고 영향받는 결과·검증을 다시 확인한다.
- 이미 처리한 동일 답변: 중복 반영하지 않고 현재 결과와 다음 작업을 확인한다.

형식이 다르거나 질문 ID가 없어도 문맥이 명확하면 내용을 받아들인다.
출처·기록 방식이 없으면 미상으로 표시하고 실제 판단에 필요한 정보만 추가로 묻는다.
사용자 요약을 담당자의 직접 인용처럼 표현하지 않는다.
반영 기록에 마지막으로 검토한 사용자 내용과 적용 범위를 남겨 다음 재개 시 비교할 수 있게 한다.
식별값을 쓸 경우 실제로 산출한 값만 기록한다.

## 상태

상태는 CLI 검토 영역에서 관리한다. 사용자 영역의 문구나 전달 여부를 대신 바꾸지 않는다.
질문 초안은 준비, 전달했다는 사용자 기록이 있으면 사용자 전달,
답변이 기록되면 답변 검토, 불명확하면 재확인 필요, 조건을 적용하면 반영으로 표시한다.
반영과 검증 완료는 구분한다. 이전 답을 대체하면 그 연결과 과거 근거를 남긴다.
답변 대기 중에도 그 답에 의존하지 않는 작업은 계속한다.
