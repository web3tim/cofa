# 선택형 실험 절차

방법의 우열이 불분명하고 비교가 중요한 판단을 바꿀 때 사용한다.
사용자가 요청했거나 실험의 필요성에 동의한 범위에서 진행한다. 모든 과제에 실험 단계를 추가하지 않는다.
안내만 허용된 경우에는 실험 계획과 다음 요청을 제안하고 실행했다고 기록하지 않는다.

## 비교를 준비하기

목표, 반드시 지킬 조건, 개선할 기준, 허용된 시간·비용을 현재 자료에서 확인한다.
지표는 출처와 계산 방법을 적고, 수치화가 적합하지 않으면 판정 기준과 관찰 근거를 정한다.
값이나 가중치를 임의로 업무 규칙으로 확정하지 않는다. 필요한 업무 확인은 기존 수동 질문 절차를 따른다.

기준선은 현재 결과 또는 가장 단순한 실행 가능한 방법으로 잡는다.
입력·설정·실행 방법·결과 위치를 남기고 같은 상태로 다시 비교할 수 있게 보존한다.
기준선의 필수 조건 충족 여부부터 확인한다. 위반한 기준선을 유효한 완료 결과라고 부르지 않는다.
기준선이 없거나 아직 실행할 수 없으면 준비 상태와 막힌 이유를 기록한다.

## 기준선 → 가설 → 비교 → 사용자 판단 → 재검증

1. **기준선:** 실제 결과와 비용을 관찰한다. 이미 유효한 증거가 있으면 불필요하게 재실행하지 않는다.
2. **가설:** 바꿀 요인, 기대 효과, 나빠질 수 있는 성질, 가설을 기각할 관찰을 제안한다.
   사용자가 고르지 않은 가설은 제안으로 남긴다. 이미 정한 선택은 다시 승인받지 않는다.
3. **비교:** 선택된 가설을 허용 범위에서 시험한다. 입력과 평가 기준을 맞추고 차이를 명시한다.
   기준선, 후보, 필수 조건 위반, 품질과 비용, 실행 상태를 함께 보여 준다.
4. **사용자 판단:** 관찰과 추천을 구분하고 채택·기각·보류를 사용자가 판단하도록 코칭한다.
   결정이 없으면 미결정으로 남긴다. 사용자가 밝히지 않은 이유를 만들어 적지 않는다.
5. **재검증:** 채택 요청을 받으면 적용된 최종 결과와 영향받는 조건을 확인한다.
   수정 전·표본에서 얻은 근거만으로 최종 결과가 검증되었다고 하지 않는다.

후보는 비교 중인 결과로 분리하고 채택 전 운영 기본값이나 제출 결과를 조용히 교체하지 않는다.
품질이 좋아져도 필수 조건을 어긴 후보는 충족안으로 추천하지 않는다.
절충이 업무 우선순위에 달렸다면 실제 비교 결과를 근거로 담당자 질문 초안을 만든다.

## 실험의 범위와 종료

- 입력과 설정, 결과 버전, 평가 기준이 다르면 같은 조건의 비교인지 먼저 점검한다.
- 반복마다 결과가 달라질 수 있으면 그 변동을 확인할 방법을 정하고 한 번의 결과를 일반화하지 않는다.
- 축소한 입력은 선택 이유와 제외 범위를 기록한다. 채택할 때 요구되는 적용 범위를 다시 확인한다.
  입력 변화에 대응하는 것이 요구사항이면 변화된 입력에서도 필요한 성질을 확인한다.
- 예상 비용과 실제 측정치를 구분한다. 숫자를 얻지 못했다면 미측정으로 둔다.
- 종료 조건은 현재 과제의 완료 기준, 남은 자원, 추가 실험의 판단 가치로 정한다.
  고정된 시간이나 횟수를 모든 과제에 강제하지 않는다. 중단 시 후보와 미완료 검증을 남긴다.

## 기록과 다음 요청

`PLAN.md`의 선택형 실험 항목에 기준선·가설·평가 범위·종료 조건·실제 사용자 결정을 남긴다.
`EVIDENCE.md`에는 비교 입력, 실행과 결과, 위반·손실, 적용 후 재검증을 연결한다.
사용자 결정 전에는 비교 해석을 돕는 프롬프트를, 적용 뒤에는 필요한 재검증 요청을 제안한다.
실험이 이미 요청된 경우 허용된 조사·측정은 이어가며 코칭 때문에 매번 재승인을 요구하지 않는다.
