# 짧은 요청을 이어가는 워크플로우

## 최초 시작

1. 명시된 작업 경로가 있으면 사용한다. 없으면 현재 작업폴더의 자료와 기존 기록을 확인한다.
   스킬 배포 폴더 자체를 과제로 간주하지 않는다. 과제가 없거나 후보가 여럿일 때만 위치를 묻는다.
2. 기존 PLAN·QUESTIONS·EVIDENCE가 있으면 읽고 사용자 변경과 이전 허용 범위를 복원한다.
   기본 기록 위치는 현재 작업의 `task-notes/`다. 다른 위치를 쓰는 기존 계획이 있으면 따른다.
   현재 작업 밖을 광범위하게 검색하지 않는다. 기록 위치를 복원할 수 없을 때만 한 번 묻는다.
   과제 폴더 안의 `.agents/skills/workflow/`는 설치된 방법론이며 과제 입력으로 취급하지 않는다.
3. 새 작업이면 필요한 빈 기록을 준비한다. 기존 파일은 보존하고 이어가기 항목만 필요한 만큼 추가한다.
4. 자료에서 목표·완료 기준·제약을 추출하고 가장 영향이 큰 미확인 사항을 고른다.
5. 현재 단계, 이번에 파악한 내용, 다음 작업, 사용자 행동을 간결하게 안내한다.
   프롬프트 코칭 지침에 따라 지금 요청할 이유, 대상·초안, 사용자가 판단할 부분과 확인할 결과를 안내한다.
   정해진 긴 프롬프트를 복사하라고 요구하지 않는다.

## 단계 선택

| 단계 | 진행할 일 | 다음 단계로 넘어갈 근거 |
|---|---|---|
| 파악 | 자료·요구·제약·미확인 사항 정리 | 중요한 요구에 근거와 확인 방법이 연결됨 |
| 계획 | 위험·의존성·대안·우선순위 결정 | 다음 작업과 완료 관찰이 분명함 |
| 실행 | 요청 범위의 작은 결과 생성·수정 | 요구한 결과를 실제로 확인할 수 있음 |
| 검증 | 결과와 요구 대조, 관련 실패 조건 확인 | 통과·실패·미검증 범위와 근거가 분명함 |
| 정리 | 결과·이유·재확인 방법·남은 일 전달 | 요구된 산출물과 필수 검사가 충족되었는지 판단 가능함 |

이는 의무적인 승인 단계가 아니다. 한 번의 요청에서 필요한 단계를 이어 진행할 수 있다.
안내만 요청한 작업에서는 실행 방법을 안내하며, 제품 구현을 임의로 시작하지 않는다.
기존에 구현까지 요청받았다면 재개할 때 구현 허가를 다시 묻지 않는다.
추가 조건이 확인되면 영향을 받는 단계로 돌아간다. “정리해”가 미완료 조건을 없애지는 않는다.

## 이어가기 기록

`PLAN.md`에 현재 단계·진행 상태·사용자 요청 범위·작업폴더·기록 파일 경로를 남긴다.
다음 작업, 사용자가 할 일, 대기 질문, 마지막으로 검토한 답변과 반영 범위를 함께 남긴다.
중요한 결정이나 상태가 달라질 때 갱신하고 모든 사소한 동작을 문서화하지 않는다.
짧은 응답과 이 기록만으로 다음 행동을 알 수 있게 한다.
현재 필요한 프롬프트 초안은 CLI 제안·미전송으로 구분하고 실제 사용자 요청과 별도로 둔다.
사용자가 실제로 선택·수정해 보낸 내용이 있을 때만 그 근거를 기록한다.
선택형 실험·이해 확인·직접 검증·답변 연습은 선택 여부, 현재 상태, 다음 행동만 필요한 만큼 추가한다.
이전 버전의 기록을 교체하거나 사용하지 않는 활동의 빈 칸을 모두 채우게 하지 않는다.

## “기록했어”를 받았을 때

현재 활동과 PLAN에 저장된 실제 기록 위치를 먼저 확인한다.
직접 확인·설명·연습 기록을 기다리는 중이면 해당 EVIDENCE 또는 사용자 지정 파일을 읽고 관련 절차로 이어간다.
동시에 여러 기록을 기다리고 있다면 알려진 파일의 변경을 확인하고, 대상을 식별할 수 없을 때만 묻는다.
아래는 담당자 질문·답변을 기록한 경우의 처리다.

1. 알려진 PLAN과 QUESTIONS를 디스크에서 다시 읽는다. 이전 대화의 답변을 그대로 재사용하지 않는다.
2. 사용자 작성 내용과 기존 CLI 검토 내용을 대조해 신규·수정·미변경·누락을 구분한다.
3. 답변의 적용 범위와 현재 지시문 간 충돌을 확인한다. 필요한 최소 질문만 사용자에게 넘긴다.
4. 명확해진 부분은 요구·결정·결과·검증 항목에 연결한다. 허용된 반영 작업은 이어 수행한다.
5. 사용자 원문은 유지하고 CLI 검토 영역과 계획의 이어가기 항목을 갱신한다.
6. 이번에 바뀐 점과 남은 미확인 사항을 짚고, 다음 요청의 목적·대상·초안과 사용자가 판단할 부분을 안내한다.
   초안을 새로 보낸 것으로 간주하지 않으며 이미 허용된 작업은 계속한다.

질문 ID나 형식이 빠져도 대상이 명확하면 받아들인다. 매번 파일 경로나 ID를 다시 요구하지 않는다.
유효한 답변이 없는 경우에는 실제로 비어 있는 부분을 알려준다. 대기 중 독립 작업은 계속한다.
미변경 답변에 같은 결정을 중복 적용하거나 같은 질문을 다시 생성하지 않는다.
다만 답변이 같아도 연결된 결과물이 바뀌었다면 필요한 검사만 다시 판단한다.

## 답변이 수정되거나 기록이 충돌할 때

사용자 영역을 원래 내용으로 되돌리지 않는다. 이전 반영 내용과 달라진 조건을 CLI 검토 영역에 남긴다.
과거 근거를 지우지 않고 영향받는 결과·검증의 유효성을 다시 판단한다.
명시된 조건과 충돌하는 답은 CLI가 임의로 어느 쪽이 우선인지 결정하지 않는다.
독립된 명확한 답은 반영하고 충돌하는 부분만 보류한다.

## 세션 재개와 대기

새 세션의 “이어서”도 같은 기록을 읽는 것으로 시작한다.
저장된 완료·허용 범위를 현재 자료 및 실제 결과와 대조한다. 오래된 메모만으로 완료를 확정하지 않는다.
업무 답변 대기는 전체 작업 중지가 아니다. 의존하는 작업과 독립 작업을 구분한다.
파일이 바뀌어도 자동으로 깨우거나 감시하지 않는다. 사용자가 짧게 알려주면 읽는다.
