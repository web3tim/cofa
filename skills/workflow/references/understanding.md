# 이해 확인과 답변 연습

중요한 결정·구현을 사용자가 설명해 보고 싶거나, 실제 작업을 바탕으로 사후 질문을 연습할 때 읽는다.
두 활동은 선택 사항이다. 이해 확인을 모든 작업의 통과 관문으로 만들지 않는다.
사용자의 숙련도, 남은 시간, 현재 요청에 맞추고 고정된 시험 형식이나 답변 시간을 가정하지 않는다.

## 내 설명 확인

사용자가 설명을 보내지 않았다면 현재 작업에서 중요한 결정 또는 처리 흐름 하나를 골라
자기 말로 설명할 지점을 안내한다. 이미 보낸 설명이 있으면 그대로 검토하고 다시 쓰게 하지 않는다.

설명은 실제 파일·결정 기록·실행 증거와 대조한다.
피드백은 **사실과 다른 부분**, **설명에 필요한데 빠진 부분**, **근거로 확인할 수 없는 부분**에 한정한다.
각 지적에 근거 위치와 확인할 지점을 붙인다. 문체나 전문용어 사용 여부를 능력 평가로 삼지 않는다.
사용자가 말하지 않은 의도·선택 이유를 추정하거나 답변 전체를 대신 다듬지 않는다.
근거가 불충분하면 사용자 설명이 틀렸다고 단정하지 말고 확인할 자료를 짚는다.

사용자 설명 원문과 CLI 피드백은 별도 항목으로 남긴다.
원문은 사용자가 작성했거나 실제로 보낸 말을 그대로 옮긴 것만 허용하고, 이전 설명을 덮어쓰지 않는다.
수정한 설명이 오면 그 버전과 검토 상태를 연결한다. 설명을 아직 받지 않았다면 미응답이다.
사용자가 설명이나 해설을 별도로 요청한 경우에만 제공하고, 이를 사용자의 실제 답변으로 기록하지 않는다.

## 실제 기록으로 질문 준비

현재 결과물과 `PLAN.md`, `EVIDENCE.md`, 사용자 질문 기록에서 근거가 있는 질문 후보를 고른다.
선택과 비용, 처리 흐름, 실패 시 동작, 변경 영향, 확인 방법, 협업 판단 중 해당되는 주제만 쓴다.
실제로 없었던 결정·오류·실험이나 하지 않은 사용자 확인을 질문의 전제로 넣지 않는다.
아직 근거가 없는 범위는 미확인으로 구분하고, 예상 질문을 실제 출제 문항처럼 표현하지 않는다.

사용자가 원하면 파일 위치·핵심 사실·남은 한계를 담은 짧은 확인 메모를 제공한다.
사용자 이유는 실제 발언에서만 가져오고, CLI의 해석·요약은 그렇게 표시한다.
답변을 대신 작성하거나 특정 채점 방식·점수·암기 분량을 전제로 하지 않는다.

## 답변 연습

연습을 요청받으면 관련 근거를 확인하고 질문 하나부터 제시한다.
사용자가 먼저 답할 수 있게 해당 턴에는 모범 답안을 함께 주지 않는다.
답변이 오면 질문의 하위 물음과 실제 근거를 대조해 사실 오류·누락·미확인 부분만 짚는다.
맞는 주장의 문장을 고치거나 없던 판단 이유를 보충하지 않는다.
사용자가 다음 질문을 원하면 이어가고, 종료·보류를 요청하면 그 상태를 남긴다.
설명 확인·연습 대기는 해당 활동만의 대기다. 별도로 허용된 독립 작업까지 중단시키지 않는다.

## 기록과 재개

`PLAN.md`에는 참여할 활동과 다음 행동을, `EVIDENCE.md`에는 실제 질문·사용자 답변·CLI 피드백을 둔다.
사용자가 파일에 직접 썼다면 다시 읽는다. 사용자 작성 영역을 수정하지 않는다.
답변을 읽었다는 사실과 이해·검증이 완료됐다는 판단을 구분한다.
구현이나 조건이 바뀌면 설명의 전제가 여전히 맞는지 확인하고 과거 피드백을 현재 증거로 재사용하지 않는다.
