# 결과 전달과 설명

현재 요청의 제출 형식과 범위를 먼저 확인한다. 지정 문서를 임의로 교체하지 않는다.
기존 작업 기록에서 필요한 내용을 가져오고 같은 내용을 여러 문서에 중복 관리하지 않는다.

설명할 내용은 다음 중 실제 작업에 해당하는 것만 고른다.

- 목적과 완료 범위, 미완료 사항
- 중요한 선택의 이유와 고려한 대안
- 실제로 얻은 결과와 재확인 경로
- 업무상 확인된 조건, 잠정 가정, 남은 질문
- 정확성·성능·사용성의 확인 범위와 한계
- 다른 사람이 실행하거나 읽을 때 필요한 환경과 순서

## 주체와 근거

담당자의 확인, 사용자의 판단, AI의 제안, 도구의 관찰을 구분한다.
AI가 자율적으로 내린 결정을 사용자가 직접 선택했다고 서술하지 않는다.
관찰 사실과 원인에 대한 추론을 분리한다.
기록되지 않은 과거 대화나 작업 과정은 추측으로 복원하지 않는다.

## 문제 해결 사례

실제로 발생한 사례가 있다면 관찰 → 가설 → 조사 → 선택·수정 → 재검증으로 설명한다.
받아들이거나 바꾼 제안이 있다면 판단 근거를 연결한다.
반드시 AI를 반박한 사례가 있어야 하는 것은 아니다. 타당한 제안을 채택했다면 그 확인 근거를 쓴다.
실행하지 않은 검사, 겪지 않은 문제, 확인받지 않은 조건을 사례로 만들지 않는다.

## 재확인 가능한 전달

파일·명령·화면·출력의 위치는 실제 존재 여부를 확인한다.
수행하지 못한 검사는 재확인 절차와 미검증 상태로 남긴다.
작성한 문서와 현재 결과물이 일치하는지 마지막으로 대조한다.
제출·업로드·배포 요청이 있다면 그 동작의 실제 결과를 별도로 확인한다.
