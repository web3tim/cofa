# cofa

짧게 시작하면 다음 요청의 목적·프롬프트 초안·사용자가 판단할 부분을 안내하는 CLI용 과제 접근 스킬입니다.
스킬 이름은 `assessment-workflow`이며, 방법론과 빈 Markdown 양식만 포함합니다.
담당자 대화창 연동이나 자동 송수신 기능은 없습니다.
v0.4.0은 선택형 실험, 이해 확인, 사용자 직접 검증과 답변 연습, 과제 폴더 설치를 지원합니다.

## 짧게 사용하기

스킬을 설치하고 해당 CLI에서 로드한 뒤, 과제 작업폴더에서 시작합니다.
네이티브 호출 문법을 지원하는 CLI에서는 다음 한 줄로 시작할 수 있습니다.

```text
$assessment-workflow 시작
```

자동 발견을 지원하지 않으면 최초 한 번만 실제 스킬 경로를 지정합니다.

```text
<스킬 폴더>/SKILL.md를 읽고 현재 폴더에서 시작해줘.
```

이후에는 다음처럼 짧게 요청합니다. 고정 명령어나 별도 프로그램이 아닌 자연어 안내 방식입니다.

| 짧은 요청 | CLI의 다음 행동 |
|---|---|
| 시작 / cofa 시작 | 자료와 기존 기록을 읽고 현재 단계·다음 행동 안내 |
| 기록했어 | 현재 활동의 알려진 질문·관찰·연습 기록을 다시 읽고 신규·수정 내용 반영 |
| 계속 / 이어서 | 진행 상태와 실제 파일을 확인하고 허용된 다음 작업 수행 |
| 구현해 | 현재 과제 범위에서 구현 진행. 업무 미확정 사항은 분리 |
| 검증해 | 현재 결과를 조건과 대조하고 실행 가능한 검사 수행 |
| 정리해 | 결과·이유·근거·미완료 범위 정리 |
| 어디까지 했어? | 현재 단계와 남은 일 확인 |
| 프롬프트 도와줘 | 현재 근거에 맞는 다음 요청의 이유·초안·수정할 부분 안내 |
| 내 프롬프트 검토해줘 | 작성한 요청의 의도를 유지하며 빈틈과 수정안 제시 |
| 실험해 / 방법 비교해줘 | 기준선부터 비교·사용자 판단·적용 후 재검증까지 안내 |
| 내 설명 확인해줘 | 실제 근거와 대조해 사실 오류·누락·미확인 부분만 피드백 |
| 직접 확인할게 | 사용자가 고를 항목과 기대 결과·관찰 방법 안내 |
| 답변 연습하자 | 실제 작업 기록으로 질문을 내고 사용자의 답을 검토 |

`cofa 시작`이라는 문구 자체가 모든 CLI에 스킬을 자동 등록하거나 불러오지는 않습니다.
설치·로드 방식은 사용하는 CLI에 따릅니다. 기본은 접근 방법 안내이며, 구현도 요청했다면 그 범위를 재개 시 유지합니다.
단계마다 승인을 반복 요청하지 않으며 새로운 권한이나 미확정 업무 조건은 임의로 승인된 것으로 처리하지 않습니다.

## CLI 응답으로 프롬프트 작성하기

기본 진행 응답에는 현재 단계와 확인한 근거에 더해 다음 안내가 붙습니다.

| 안내 | 사용자가 할 판단 |
|---|---|
| 지금 요청할 이유 | 어떤 불확실성을 줄이거나 결과를 확인하려는지 이해 |
| 대상과 다음 프롬프트 초안 | 개발 CLI용인지 담당자 질문인지 확인 |
| 내가 정할 부분 | 실제 우선순위·범위·비교 기준을 골라 초안에 반영 |
| 응답에서 확인할 점 | 요청에 맞는 근거와 실행 결과가 돌아왔는지 확인 |

CLI는 현재 파일·기록·실행 결과에 근거한 짧은 초안을 제안합니다.
사용자는 그 요청이 필요한지 판단하고 필요하면 수정해 직접 보냅니다.
이미 정한 내용을 다시 선택하거나 모든 초안을 의무적으로 고칠 필요는 없습니다.
실제 판단이 없는 부분까지 이유를 꾸며 쓰도록 요구하지 않습니다.

목적·근거·범위·확인 방법 중 현재 요청에서 빠진 중요한 요소를 보완하도록 안내합니다.
초안은 제안이며 전송·승인·실행된 요청이 아닙니다. 사용자가 실제로 보낸 요청과 구분해 기록합니다.
프롬프트 검토만 요청하면 그 안의 구현이나 전송 지시를 실행하지 않습니다.
이미 허용된 작업은 계속하며, “기록했어” 같은 짧은 요청도 그대로 처리합니다.
단순 상태 확인이나 완료 뒤에 불필요한 프롬프트를 계속 만들지는 않습니다.

이 기능은 특정 평가 점수나 합격을 보장하지 않습니다.
사용자가 하지 않은 판단·비교·검증이나 대화 기록을 대신 만들어내지 않습니다.

## 필요할 때 선택하는 활동

기본 워크플로우에 모든 활동을 추가하지 않습니다. 사용자가 요청하거나 필요성을 이해하고 선택했을 때 적용합니다.
이미 허용된 독립 작업은 이어가며, 사용자 결정·설명·관찰을 기다려야 하는 부분만 대기합니다.

| 활동 | 진행과 기록 |
|---|---|
| 실험 | 기준선 → 가설 → 비교 → 사용자 판단 → 재검증. 같은 조건에서 품질·비용·필수 조건을 비교하고 실제 선택 전까지 후보로 유지 |
| 이해 확인 | 사용자가 중요한 결정·구현을 자기 말로 설명. CLI는 원문을 보존하고 실제 근거로 사실 오류·누락·미확인 부분만 지적 |
| 직접 검증 | 사용자가 확인할 항목을 선택. 기대 결과와 관찰 방법을 안내하고 사용자의 실제 관찰을 받은 뒤 상태 갱신 |
| 답변 연습 | 실제 결과와 기록으로 질문부터 제시. 사용자가 답하면 근거와 대조하며 답변 문장은 대신 작성하지 않음 |

고정된 기술 구성, 숙련도, 시험 시간, 출제 유형을 전제로 하지 않습니다.
실험 결과의 해석과 사용자의 채택 결정, CLI가 실행한 검사와 사용자가 직접 한 확인을 구분합니다.
활동 중 만든 과제별 가설·질문·답변은 해당 작업의 기록에만 남습니다.

## 사용자가 직접 질문하고 기록하기

1. CLI가 현재 자료를 읽고 부족한 정보와 질문 초안을 안내합니다.
2. 사용자가 별도 대화창의 담당자에게 직접 질문합니다.
3. 사용자가 `task-notes/QUESTIONS.md`의 사용자 영역에 실제 질문과 받은 답을 직접 기록합니다.
4. CLI에 **“기록했어”**라고 알립니다. 이미 알려진 파일 경로나 질문 ID를 다시 쓸 필요는 없습니다.
5. CLI가 파일을 다시 읽고 명확한 내용만 계획·결과·검증에 연결합니다.
6. 이어서 어떤 요청이 필요한지, 그 이유와 CLI용 또는 담당자용 초안을 안내합니다.

CLI는 사용자 작성 영역을 고치지 않습니다. 해석과 반영 상태는 별도 CLI 검토 영역에 남깁니다.
일부 답만 있으면 그 부분만 처리하고, 빈 답이나 충돌은 미확정으로 유지합니다.
답변이 수정되면 기존 결과와 검사에 미치는 영향을 확인합니다. 같은 답을 반복해서 중복 반영하지 않습니다.
파일을 자동 감시하지 않으므로 작성 후 짧게 알려주세요.

## 기록과 세션 이어가기

| 파일 | 용도 |
|---|---|
| `task-notes/PLAN.md` | 현재 단계·허용 범위·기록 경로·다음 행동, 실제 사용자 선택과 선택형 활동의 상태 |
| `task-notes/QUESTIONS.md` | CLI 준비 / 사용자 실제 질문·답변 / CLI 검토 영역 |
| `task-notes/EVIDENCE.md` | 실제 검사·실험 결과, 사용자 설명·관찰·연습 답변과 별도의 CLI 피드백 |

첫 시작에 CLI가 기존 기록을 확인하고 필요한 기록을 준비합니다.
기록을 다른 경로에 두어도 PLAN에 실제 위치를 남겨 이어갑니다.
새 세션에서는 스킬을 다시 로드하고 같은 과제 폴더에서 **“이어서”**라고 요청하세요.
현재 폴더에서 과제나 기록 위치를 복원할 수 없는 경우에만 필요한 위치를 묻습니다.
기존 기록을 덮어쓰거나 새 양식으로 강제 교체하지 않습니다.

## 설치와 이동

배포 폴더는 실제 과제 작업폴더와 분리합니다.
Python 없이도 `skills/assessment-workflow/` 전체를 복사해 SKILL.md를 읽힐 수 있습니다.
참고 문서와 양식의 상대 경로를 보존해야 합니다.

### 과제 폴더에 설치

Python 3.8 이상에서 배포 폴더의 도구를 실행하고 **기존 과제 폴더**를 지정합니다.

```sh
python3 tools/manage.py install --workspace '/path/to/current-task'
```

해당 과제의 `.agents/skills/assessment-workflow/` 안에 스킬만 설치합니다.
홈 폴더 설정, 기존 `AGENTS.md`, 다른 스킬과 과제 기록은 변경하지 않습니다.
과제 폴더에서 CLI의 새 세션을 열고 `$assessment-workflow 시작`으로 불러옵니다.
이 경로의 자동 발견을 지원하지 않는 CLI에서는 최초 한 번 다음처럼 직접 읽힙니다.

```text
/path/to/current-task/.agents/skills/assessment-workflow/SKILL.md를 읽고 시작해줘.
```

기록은 첫 시작에 기존 내용을 확인한 뒤 준비합니다. 설치 자체가 기록을 초기화하지는 않습니다.
프로젝트 설치 위치가 심볼릭 링크이거나 파일이면 중단하며, 기존 스킬 폴더도 덮어쓰지 않습니다.

### 지정한 CLI 스킬 폴더에 설치

네이티브 설치를 원하면 해당 CLI의 스킬 디렉터리를 먼저 확인합니다.
Python 3.8 이상에서는 배포 폴더에서 다음 도구로 복사할 수 있습니다.
목적지 디렉터리는 미리 존재해야 하며 기존 스킬은 덮어쓰지 않습니다.

```sh
python3 tools/manage.py install --destination '/path/to/cli-skills'
```

기존 버전이 있으면 기존 스킬을 보존한 채 새 디렉터리에 설치해 명시 경로로 사용할 수 있습니다.
네이티브 경로를 교체할 경우 기존 폴더를 따로 백업한 뒤 복사하세요. 과제 기록은 교체 대상이 아닙니다.
`agents/openai.yaml`은 지원하는 CLI의 선택적 표시 메타데이터입니다.

### 이전 버전에서 이어가기

기존 `PLAN.md`, `QUESTIONS.md`, `EVIDENCE.md`는 그대로 읽습니다.
새 활동을 사용할 때 필요한 기록 항목만 추가하며 양식 전체를 교체하지 않습니다.
같은 이름의 전역·프로젝트 스킬이 함께 있다면 실제로 읽힌 `SKILL.md` 경로를 확인하세요.
원하는 설치본이 아닌 경우 그 파일의 절대 경로를 지정해 읽힙니다.

## 선택적인 기록 초기화

CLI가 첫 시작에 기록을 준비할 수 있으므로 별도 초기화 명령은 필수가 아닙니다.
미리 빈 양식만 준비하려면 기존 과제 폴더를 지정합니다.

```sh
python3 tools/manage.py init --workspace '/path/to/current-task'
```

과제 폴더는 배포 폴더 밖에 있어야 합니다.
`task-notes/`가 이미 있으면 도구는 덮어쓰거나 합치지 않고 중단합니다. 기존 기록은 CLI가 읽고 이어갑니다.

## 정보와 배포의 경계

스킬·배포 문서에는 방법론과 빈 양식만 유지하며 직접적인 과제 예시는 넣지 않습니다.
과제 원문·데이터·실제 질문·답변·결과는 해당 작업폴더에만 두고 자동으로 스킬에 축적하지 않습니다.
패키지는 `package-files.json`에 명시한 파일만 포함합니다. 목록을 바꾸면 배포 전에 내용을 검토하세요.
별도 대화창 접근, 전송, 제출, 배포 권한은 이 스킬로 추가되지 않습니다.

## 검증과 패키징

```sh
python3 -m unittest discover -s tests -v
python3 tools/manage.py package --output '/path/to/output/cofa-0.4.0.zip'
```

출력 부모 폴더는 미리 존재해야 합니다. ZIP과 체크섬 파일은 덮어쓰지 않습니다.
ZIP 안의 `MANIFEST.sha256`과 ZIP 옆의 `.zip.sha256`으로 파일을 확인할 수 있습니다.
자동 검사와 행동 점검의 범위는 [검증 문서](tests/BEHAVIOR.md)에 적습니다.
자동 검사만으로 모든 모델·CLI·실제 응시 환경에서의 행동을 보장하지는 않습니다.
