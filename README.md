# workflow

자료 파악부터 실행·검증·정리까지, 짧은 요청으로 이어가는 CLI용 과제 접근 스킬입니다.
현재 근거를 바탕으로 다음 프롬프트와 사용자가 판단할 부분을 안내합니다.
**v0.5.0** — 방법론과 빈 양식을 여섯 Markdown 파일로 구성합니다.

## 설치

Node.js 22.20 이상이 있는 환경에서 **과제 폴더로 이동한 뒤** 실행하세요.

```sh
npx -y skills add web3tim/cofa -s workflow -a codex -y
```

공개 GitHub 저장소에서 받아 현재 과제의 `.agents/skills/workflow/`에 설치합니다.
같은 이름의 설치본을 교체할 수 있으므로 직접 수정한 스킬은 먼저 백업하세요.
과제 기록은 아래의 별도 폴더에서 유지합니다.

같은 과제 폴더에서 Codex CLI의 새 세션을 열고 시작하세요.

```text
$workflow 시작
```

다른 CLI에서 자동 발견되지 않으면 설치된 `SKILL.md`의 실제 경로를 지정해 읽도록 요청하세요.
이전 `assessment-workflow` 설치본을 유지할 경우 어떤 스킬을 읽는지 확인하세요.

## 여섯 파일

| 파일 | 역할 |
|---|---|
| [README.md](README.md) | 설치와 사용 안내 |
| [SKILL.md](SKILL.md) | 스킬 진입점과 단계별 진행 |
| [AGENTS.md](AGENTS.md) | CLI의 판단·코칭·기록·검증 원칙 |
| [PLAN.md](PLAN.md) | 현재 상태, 요구사항, 결정, 다음 행동의 빈 양식 |
| [QUESTIONS.md](QUESTIONS.md) | 담당자에게 직접 질문하고 답을 적는 빈 양식 |
| [EVIDENCE.md](EVIDENCE.md) | 실제 검사·관찰·실험·피드백의 빈 양식 |

설치 폴더의 파일은 재사용 원본입니다. 처음 시작하면 CLI가 기존 기록을 확인한 뒤
과제의 `task-notes/`에 필요한 양식을 준비합니다. 실제 내용은 그곳에만 적습니다.
기존 기록의 위치와 내용은 유지하며, 프로젝트의 기존 `AGENTS.md`도 교체하지 않습니다.

## 짧게 이어가기

1. **시작** — 자료를 읽고 현재 단계, 부족한 정보, 다음 요청을 안내받습니다.
2. 담당자 확인이 필요하면 사용자가 별도 대화창에서 직접 질문합니다.
3. 사용자가 `task-notes/QUESTIONS.md`의 사용자 영역에 실제 질문과 답변을 적습니다.
4. **기록했어** — CLI가 파일을 다시 읽고 명확한 답을 계획과 다음 작업에 반영합니다.
5. **계속**, **구현해**, **검증해**, **정리해** — 필요한 작업을 짧게 요청합니다.

**프롬프트 도와줘**, **내 프롬프트 검토해줘**로 요청 작성에 도움을 받을 수 있습니다.
CLI는 요청할 이유, 대상, 짧은 초안, 직접 판단할 부분과 결과에서 확인할 점을 안내합니다.
초안은 `CLI 제안·미전송`이며, 실제로 보낸 요청과 구분합니다. 매번 길게 다시 쓸 필요는 없습니다.

필요하면 **실험해**, **내 설명 확인해줘**, **직접 확인할게**, **답변 연습하자**를 선택하세요.
실험은 기준선 → 가설 → 비교 → 사용자 판단 → 재검증으로 진행합니다.
설명·연습은 실제 기록을 근거로 사실 오류와 빠진 부분을 확인합니다.

새 세션에서도 같은 폴더에서 스킬을 불러온 뒤 **이어서**라고 요청하면 됩니다.
담당자 대화창은 연동되지 않으며, 파일도 자동 감시하지 않습니다. 기록 후 짧게 알려주세요.
구체적인 과제 자료·대화·사례·결과는 스킬이나 배포본에 넣지 않습니다.
