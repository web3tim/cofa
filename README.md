# cofa

자료가 주어진 과제에서 목표와 제약을 파악하고, 부족한 업무 정보를 직접 확인하며,
실행 결과를 검증하도록 돕는 CLI용 방법론 스킬입니다. 특정 업무의 정답이나 구현을 제공하는 패키지가 아닙니다.

스킬 이름은 `assessment-workflow`입니다. 한국어 안내, 빈 작업 기록 양식,
선택적으로 사용할 오프라인 복사·패키징 도구가 들어 있습니다.
방법론은 플랫폼과 언어에 독립적이며 외부 API, 계정, 네트워크 연결을 요구하지 않습니다.

## 다른 CLI에서 시작하기

압축을 푼 폴더를 **과제 작업폴더와 별도로** 둡니다. CLI가 파일을 읽을 수 있도록 접근 가능한 위치를 선택하세요.
설치 없이 다음 지시에서 실제 절대 경로만 바꾸어 사용할 수 있습니다.

```text
<압축을 푼 폴더>/skills/assessment-workflow/SKILL.md를 읽고 적용해줘.
현재 과제 작업폴더는 <과제 폴더>야. 우선 과제 접근 방법을 안내해줘.
빠진 정보를 찾아 내가 담당자에게 직접 물어볼 질문을 준비하고,
답변을 기록할 Markdown 파일과 이후 다시 읽는 절차를 알려줘.
```

네이티브 스킬 검색을 지원하는 CLI라면 그 CLI가 실제로 사용하는 스킬 디렉터리를 확인한 뒤
`skills/assessment-workflow/` 폴더 전체를 복사합니다. 기존 스킬은 덮어쓰지 마세요.
`$assessment-workflow` 같은 호출 문법은 해당 CLI가 지원할 때만 사용합니다.
`agents/openai.yaml`은 지원하는 호스트의 선택적 표시 메타데이터이며 방법론의 필수 요소가 아닙니다.

Python 3.8 이상이 있으면 복사 도구를 사용할 수 있습니다. 아래 명령은 압축을 푼 배포 폴더에서 실행하며 경로는 실제 경로로 바꾸세요.
이 도구는 이미 존재하는 목적지 디렉터리를 요구하며, 같은 이름의 스킬이 있으면 중단합니다.

```sh
python3 tools/manage.py install --destination '/path/to/cli-skills'
```

Python이 없어도 Markdown 파일을 직접 읽고 빈 양식을 수동으로 복사하면 됩니다.
배포 폴더 전체를 옮기거나 스킬 폴더 전체를 복사해야 상대 경로의 참고 문서와 양식이 유지됩니다.

## 과제별 기록 준비

CLI가 기존 과제 기록을 먼저 확인하도록 하세요. 새 기록이 필요하면 다음 명령을 배포 폴더에서 실행합니다.

```sh
python3 tools/manage.py init --workspace '/path/to/current-task'
```

과제 폴더는 미리 존재해야 하며 배포 폴더 밖에 있어야 합니다.
`task-notes/`가 이미 있으면 도구는 아무것도 덮어쓰거나 합치지 않고 중단합니다.
기존 기록을 재사용하거나, 현재 작업 규칙에 맞는 다른 위치에 필요한 양식만 수동으로 복사하세요.

| 파일 | 용도 |
|---|---|
| `task-notes/PLAN.md` | 목표, 요구사항, 근거, 결정, 다음 행동 |
| `task-notes/QUESTIONS.md` | 질문 초안, 사용자가 기록하는 답변, 반영할 내용 |
| `task-notes/EVIDENCE.md` | 실제 검사, 관찰 결과, 문제 해결과 미검증 범위 |

이 파일들은 사용자가 Markdown으로 직접 편집할 수 있습니다. CLI에 작성·갱신을 요청할 수도 있지만,
받지 않은 답변이나 실행하지 않은 검사를 만들어 기록해서는 안 됩니다.

## 별도 대화창과의 수동 절차

1. CLI가 자료를 살펴보고 중요한 미확인 사항과 전달할 질문을 준비합니다.
2. **사용자가** 그 질문을 별도 대화창의 담당자에게 직접 전달합니다.
3. **사용자가** 받은 답을 `QUESTIONS.md`의 해당 질문 아래에 씁니다.
   원문인지 사용자 요약인지, 답변자·출처·확인 가능한 시점을 표시합니다.
4. CLI에 수정한 파일 경로와 질문 ID를 알려 다시 읽게 합니다.
5. CLI가 답변과 해석을 구분하고, 모순이 있으면 재확인할 질문을 준비합니다.
6. 명확해진 조건을 계획과 필요한 검사에 연결합니다. 답변 대기 중에도 독립적인 작업은 진행합니다.

답변 기록 후에는 다음처럼 요청할 수 있습니다.

```text
<과제 폴더>/task-notes/QUESTIONS.md에 답변을 기록했어.
새 답변을 다시 읽고 기존 조건과의 충돌, 바뀌는 판단, 다음 행동을 정리해줘.
관련 계획과 검증 항목을 갱신하되, 아직 실행하지 않은 검사는 미검증으로 남겨줘.
```

대화창 연동, 자동 송수신, 답변 수집 기능은 없습니다.
이 스킬만으로 구현·전송·제출 권한이 추가되지 않습니다. 실행은 현재 사용자의 요청 범위와 환경 규칙을 따릅니다.

## 정보 분리

배포하는 스킬에는 방법론과 빈 양식만 유지합니다.
과제의 원문, 데이터, 대화, 사례, 결과는 해당 과제 폴더에 두며 스킬에 자동 축적하지 않습니다.
이 저장소의 검증 사례는 독립적으로 만든 가상 사례입니다.
패키징 도구는 `package-files.json`에 명시한 파일만 담으며 작업 기록이나 임의의 추가 파일을 수집하지 않습니다.
이 목록을 바꾸면 포함 내용도 바뀌므로 배포 전에 검토하세요.

## 검증과 다시 패키징하기

```sh
python3 -m unittest discover -s tests -v
python3 tools/manage.py package --output '/path/to/output/cofa-0.1.0.zip'
```

출력의 부모 폴더는 미리 존재해야 합니다. 기존 ZIP이나 체크섬 파일을 덮어쓰지 않습니다.
ZIP에는 각 파일의 `MANIFEST.sha256`이 들어가고, ZIP 옆에는 `.zip.sha256` 파일이 생깁니다.
동일 파일과 동일 실행 환경에서는 동일한 ZIP 바이트를 생성합니다.

자동 검사는 복사·덮어쓰기 방지·압축 해제 후 실행·패키지 구성과 체크섬을 확인합니다.
행동 점검 방법과 확인 범위는 [검증 문서](tests/BEHAVIOR.md)를 참고하세요.
특정 CLI의 자동 발견이나 실제 평가 환경의 작동을 보장하지 않습니다.
